# 64 → 256 tokens：有界、等预算补充条件

## 决策与原因

用户提出把输出上限提高，让 Raw 和 ContractKV 尽可能正常生成完毕。采纳，新增独立的 256-token 条件；正在运行的 64-token 冻结矩阵不修改。

实际检查了 `code_context_v1_order_risk` 的原始文本：Llama 第一重复在推理说明后刚写到 Python 代码块，64 tokens 时因 `length` 终止。Mistral 第一重复也在最后数值之前因 `length` 终止。两者并不是已经观测到无限重复。Qwen 前两次重复的 20 条 Raw 见证均正常终止。提高预算因而有明确的完成率诊断价值。

但更长预算不保证得到有效证书：模型可能完成解释性回答，仍违反原来的“仅输出整数”任务契约；也可能继续触顶、margin 不足或重排后行为变化。这些结果全部保留。原 exact-normalized 评分不改，不能把含正确数字的长解释事后改算主评分正确。

## 冻结范围

- 全部原 20 个受控病例、三个原模型，各一次新进程条件，不只重测已知截断病例。
- 每个模型 80 次真实生成：Raw 见证、Raw 重复、私有命名空间的未经认证候选、认证后实际路由。最多 60 次资格 RPC，合计 240 次生成。
- 四条路径均使用 256-token 上限。上限不是强迫生成长度；正常 EOS 可以提前结束。
- 原 Prompt 字节、候选顺序、模型、greedy 设置、scope 检查、margin、EOS、PSTP、评分不变。预算作为 scope 绑定的一部分另行计算。
- 沿用 v5 的不完整见证 fail-closed 处理；缺少完整答案和 EOS 不发布证书。
- 原 120 个行为 Prompt 形状复用已有预检，最大 Prompt + 256 + EOS 为 1,023 tokens，全部小于共同 16K。没有重新复制 runtime、重新分词预检或重复计算模型全量 SHA。
- 不重复 Manifest 对照。可以与另外冻结的真实 RepoBench 诊断共用新模型进程以减少启动开销，但命名空间、条件和统计分母分开；不作为服务吞吐实验。
- 原九个单元完成并归档后才执行。具体执行代码与哈希仍需在 GPU 运行前冻结、检查、公开。

## 结果判断

分别报告 64-token 与 256-token 条件的 EOS 完成率、实际生成长度、原任务分数、输出 ID 一致性、真实资格结果、发布与完整诊断成本。三模型各一次进程，不能宣称三重复稳定性或跨来源泛化。该条件是在观察到截断后提出的预算敏感性诊断，不冒充未见独立验证。
