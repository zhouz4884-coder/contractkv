# 第二阶段第一批独立验证：完整结果与追加修正依据

54/54 个 cell、40500 次实际业务生成、36450 个未来请求已完成。源代码/输入在生成前以 99 个文件冻结并公开，三模型每种策略做三个独立服务重复。完整审计、本地 561 成员哈希验证与 CSV/JSON 独立重算均通过。

## 两组失败的实际原因线索

Qwen 的 4 次下降来自同一个 RepoBench 项目 `ahayler/s4c`、同一个 query scope。参考 raw 输出与同输入原始路径完全相同，都是较长的代码片段，其中函数调用后直接连接 `return`，构成不可解析的 Python 语句。raw 最小 margin 为 0.906–0.938，candidate 最小 margin 超过 9。后续 compiled 输出完全保持该 witness；相应未来 raw 改为更短的 `return test_dataset`，冻结 edit-similarity 从 0.06 提高到 0.10。这组结果说明近并列门槛不足以解决跨 observation 的响应形态变化。

Llama 的 3 次下降来自同一 NarrativeQA 来源 doc181、同一 query scope。参考为 “The character Virgil is not mentioned in the provided context.”；未来 compiled 改写为 “The provided context does not mention a character named Virgil.”。它们表达相同的否定，但冻结词面 F1 从 0.2 变为 0。candidate 最小 margin 为 0.09375，高于当前 0.0625，却低于原开发网格中的 0.125。这个语义等价观察只是解释，不会抹掉既定指标中的下降。

两组都使用了实际完整 prompt IDs、三个重复和原始/参考对照，没有从缺失的历史日志补造身份或 logprob。强 margin 可以降低近并列风险，当前证据不支持它对所有未来动态输入构成统一质量保证。

## 第二次准入修正与新验证

追加修正保留这批所有数据：RepoBench 使用独立的 Python 输出语法准入，参考输出只有在可解析为一个完整 Python 语句时才允许进行 GPU 认证。它不执行代码、不改写答案、不读取 gold 分数；不完整或多语句 continuation 保守走原始路径，覆盖变化将单列。candidate/EOS 最小 margin 从 0.0625 收紧到原开发网格已有的 0.125，raw 下限、成本预测、固定档位和单次尝试保持一致。

对七个已记录失败做 CPU 规则重放均会拒绝准入；这只是已见案例的控制流验证，不是新的 GPU 效果或独立成功证据。第一批 50 来源从此按已观察开发数据处理。第二批在任何新策略 forward 前，按源 ID 哈希冻结了另外 50 来源，排除了全部 412 个既往来源，每个任务族 10 个，seed 为 10672130；另取每族前两个作为十租户样本。

第二批使用 raw/修正策略、三模型、三个重复、两种会话条件，共 36 cells/27000 次业务生成。其源码、输入和审计以 112 个文件冻结，已在首次 forward 前公开。任何新结果均单独报告，不替换本报告的失败，也不把同一批数据调参后的重跑称为未见验证。

第一批完整原始包有 7 个传输分片，SHA256 为 `9a36851190d6958c2b3258275bce31ad33a4e592cb43c8a0a28bb7eb0ceda403`。原始请求、所有路由、首次分歧、witness 长度、完整输出 token IDs、参考 logprob 证据、模型注册表、包版本及执行前冻结均在包中。手稿和审稿回复文字尚待结合全部实验结果修订。
