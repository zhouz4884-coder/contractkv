# ContractKV：固定成本门禁修复与验证记录

更新：2026-10-17。**三路 DEV 和独立九单元均完成，原始包与独立复算通过。结论：该成本变体不替换原版保真 R4。**

## 修复的具体内容

旧门禁的短输入成本校准在保真长输入下失配；fan-out 又没有执行同步增量等待预算。单次失败认证会占用约四秒并传播到下一 wave readiness。现有前置概率加权期望成本、条件 GPU RPC 与完整 controller 是三个不同口径，不能把 1.64 秒直接拿来与完整 4.14 秒相除设倍数。

借鉴 Vidur 的实测执行 profiling 思路，使用已存在 DEV 的 76 次认证 RPC，按模型/家族/档位/固定长度桶构造单调冷成本经验上包络；不能确认当前完整物理驻留时按冷成本，未知形状回退 raw。仅 Qwen 有可用长输入开发数据，因此本候选不外推到 Mistral/Llama。保持旧收益 cap、资格概率项、行为 scope、margin/EOS、单次认证、输出准入及 PSTP，不同时扩大收益预估或安全授权。

fan-out 增量同步 controller 预算取原 DEV raw 全局 p99；这是准入预测预算，不是运行时硬 p99 保证。Sarathi-Serve 对长 prefill 干扰的分析帮助识别等待传播，但本修复没有引入其调度器。文献及不适用边界见[核对记录](tsc_revision_cost_fidelity_literature_notes_zh.md)。

输入打包、common client 配置加载/tenant 展开与服务端启动属于预先声明的共同准备；新服务计时从请求波开始，包含全部在线规划、实际业务、信息/认证 RPC、失败和同步等待、日志及评分。不能把时钟字段名里的 all setup 理解成包含进程启动或整个 benchmark 构造。

### 原因已经定位到成本校准支持域

Qwen/HotpotQA/L3 开发 profile 的最高有数据桶为 8192，实际最大观测约 6880 个 candidate Prompt tokens；独立来源约 13871–14619 tokens，均在模型 16K 窗口内，但超出该成本表的支持域。按冻结规则，unsupported 输入把可计入收益设为零并回退 raw。

因此 27 个 HotpotQA scope-repeat 被前置信息门禁拒绝，另有 9 个 RepoBench scope-repeat 因同步等待预算拒绝。36 次拒绝中，18 个对应原版实际已获准的 scope-repeat；这是匹配控制证据，仍不是对被拒路径额外做 GPU 认证。没有模型窗口溢出、scope 索引闲置或行为安全证据要求这些 HotpotQA 必须拒绝的结论。

原版 doc57/doc116 的 raw F1 为 0.75/0.40，分别 258 个编译未来配对均保持分数；成本变体把这些合法且有正任务分数的机会排除了。doc177 raw F1=0.50 但原版未获准，原失败保留。实际前缀工作量也对应覆盖损失：raw/原版/适配业务新 prefill 分别为 18,867,108/9,171,156/17,265,492，另计认证 0/424,290/29,118；它们是首次 scheduler 计数，不能直接换算 GPU 时间。

### L0 变化继续保留，归因没有全部闭合

原版全业务 10 次 >0.03 上升、8 次下降；适配 17 次上升、6 次下降，均为 L0，集中于同一个 RepoBench 来源 Full-Segment-Anything。相同位置 raw 重复有双向变化，但三个 raw 控制共享且相关。

按预先使用的后验案例条件，13 个策略/位置案例中，8 个 L0 变体在相同位置 raw 控制出现；5 个没有在三个 raw 控制中观察到。五个都只在某一次策略重复出现，实际输入 IDs 和 native hit 数相同；不能把这些事件一概归于原生波动，也没有据此证明策略因果关系。全部输出、分数、首个分歧与 source 簇记录保留；没有更改评分或把代码变体判为“都正确”。

### 最终工程决定

**保留保真输入与原版严格 R4 为主要实测路径；成本适配不替换默认。** 开发改善没有在新来源形成同样的覆盖/吞吐收益。当前代码仍保留可审计实验分支，全部负结果公开；不在该独立测试上扩展桶或重新设预算。

若将来继续成本优化，需要另外的开发来源覆盖 13–15K HotpotQA，联合检查收益 cap 与成本校准，再安排新的独立检验。本轮没有启动该研究，也没有追加 GPU 矩阵。L0 偶发变化、窄代码契约、生产 query 重复率和非普遍尾延迟均转为明确限制/后续问题。

九单元原始包为 403 成员、5 分卷，SHA256 `f3e8a719099559d1daf6472be789ad5f177c1ea0eccd439ff29b67349248f692`。16 个主分析、6 个补充分析、4 个归因/质量文件本地与远端独立复算完全一致，无数值差；5,400 个实际业务 Prompt IDs 和 108 个候选计划逐条匹配。全部自有 GPU worker 已退出，当前无 compute resident。
