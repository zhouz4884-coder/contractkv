# 第二阶段开发服务试跑：完整成本、覆盖与尾部

18/18 个 cell 已完成，5580 次业务生成和 290 次验证调用的实际请求、完整 prompt IDs、usage、缓存指标及任务分数通过独立审计。新策略 766 次编译未来请求没有任何任务分数下降；Mistral 另有 2 次 **raw 回退**的 >0.03 分数下降，完整保留。这里是一个开发重复，不能替代独立新 50 来源的三次正式运行。

试跑使用 V1 raw floor 0.03125、candidate/EOS floor 0.0625，固定模型/任务族档位及单次验证。正式验证采用在接触新测试输出之前收紧的 V2 raw floor 0.0625，并去掉同波同 scope 的第二份 logprob 请求。两者的实际差异写入正式冻结，未将本表冒充 V2 的最终性能。

吞吐分母包含全部业务、规划、记录、评分与同步验证等待的实际 wall，包含 warm 业务；分子沿用原未来请求口径。模型驻留和预热控制在测量之前，审计 flush 单独计时。没有离线减去验证开销。冷会话为每模板一个租户、12 个来源；fanout 为每模板十租户、5 个来源，共 50 个注册会话。实际并发均为 2，readiness 沿用两请求 wave 屏障。

与原始路径相比，三模型冷会话完整吞吐的点估计均转正，但 Mistral、Llama 增益很小，而且冷会话 p99 全部仍高于 raw。Qwen fanout 的 p99 比降档控制低 33.70%，吞吐基本持平；其直接比较的簇 bootstrap 区间仍跨 0，不能仅凭点估计宣称统计显著。Mistral、Llama 的 fanout p99 接近 raw。Llama fanout 吞吐略低于降档控制，体现减少验证与减少可复用覆盖之间的取舍。

新策略与降档控制分别有 766/1674、849/1674 次编译未来请求。调用数由 180 降至 110；验证 RPC 毫秒合计在冷会话下降约 45.3%，fanout 下降约 46.8%。这些 RPC 可重叠，合计是成本记账，不能再次加到已经计入全部等待的 wall。

本轮 117 个可尝试 scope 的事前收益预测全部放行，另有 7 个 scope 因 raw 最小 margin 不足而在验证 RPC 前拒绝，110 次实际调用中 80 次获准、30 次候选失败。因此，本轮观察到的成本下降主要伴随固定档位、单次尝试和 margin 早拒绝；**不能把它归因于收益门禁已经筛掉了大量不盈利请求**。收益门禁的真实早拒绝作用须在正式新样本上按日志核对。

额外尾部诊断按每 cell 最慢 `ceil(1%×future数)` 个请求取样，不移除原指标中的任何行。Mistral、Llama fanout 的最慢 5 个新策略请求均来自原先固定 L0 的 RepoBench，进入 RPC 前的平均额外等待分别约 22.5/17.4 ms。这支持“当前尾部主要受未编译原生路径限制”的解释；它不是单靠进一步压缩验证等待就能消除的代价。扩大这些任务的可认证范围是另一个待验证方向，本轮保持原资格范围，避免把覆盖变化混入门禁比较。

置信区间将冷会话中共享等待的两个来源作为一个簇，fanout 按整个模板含全部租户聚类；正式测试再联合抽样三个配对重复。均值使用 3000 draws，p99 使用 2000 draws，并直接给出新策略/降档控制的比较。原始 token ID 分歧、超出 witness 长度的部分、所有回退与阈值敏感性均保存在 CSV 中。分数未下降不等于逐 token 相同，也不等于完整未来输出都在认证路径内。

原始证据包 SHA256 为 `e8592d3e893fd9c60febe8c7e43180279565fc08255d39165519ceae83732f53`，223 个成员。本地重组、逐成员哈希和独立重算全部 CSV/JSON 均通过。后加的 `analysis_extra` 是引用同一冻结原始证据的独立 CPU 描述分析，没有改写已封存的包或业务记录。
