# 第二阶段：最小 margin 后端预检

新后端在 KV 提交前执行逐 token 最小 margin 检查；原有 rank-one、EOS、scope 与发布边界继续保留。原后端和原 83 项承诺文件未改变。本轮使用 raw/candidate floor=0.0625，属于预先声明开发网格中的一个预检点，尚未选为最终配置。

| 模型 | 实际请求 | 仅 rank-one 路径可通过 | 加入最小 margin 后获准 | 拒绝发布 token |
|---|---:|---:|---:|---:|
| Llama | 51 | 6 | 0 | 0 |
| Mistral | 69 | 6 | 0 | 0 |

120/120 请求均关联到真实指标和 ModelRunner 执行记录。48 次自由生成、42 次完整 logprob 请求、30 次内部验证分别保留；未获准的手动候选生成仅为负控制，不是方法已服务的编译请求。789/1575 个模型步均实测为一个活动请求，并记录输入/hidden/logit 张量形状及 padding、CUDA graph 模式。它们是模型步观测，不是逐 kernel profiler。

在原失败的首分歧位置，本轮第一重复、future prompt 上的观测如下；数值为 logprob margin：

| 模型 / 位置（从 0 开始） | 完整 LP 的目标 margin | 内部行提取的目标 margin | 实际 raw 解码 margin | 实际候选解码 margin |

| Llama / 12 | 0.015625 | 0.015625 | 0.53125 | 0.046875 |

这些是本轮重放的数值，不能补写为原失败运行的 logits。两例新见证的输出 IDs 与原业务见证相同，但 Llama 的坏输出本轮未重现；其当前 GPU 为 0，原失败编译请求在 GPU 1。Mistral 当前和原编译请求均在 GPU 1，当前手动候选输出与原坏输出相同。每请求完整 token IDs、旧来源哈希、GPU 对应关系和计算形状均可在逐请求表核对。

本轮 raw 答案最小 margin 分别为 0 和 0.03125，门禁因此能阻止这些弱见证被批准；不能把 q05 当成所有位置的下界，也不能把 API 精度下的零间隔当成实数模型 logits 严格并列的证明。原失败的逐 token LP 未保存，当前数据不能证明某个浮点机制是唯一病因。

42 个冻结文件及 75 个归档成员核验通过，本地重算 CSV 字节和 JSON 值与远端一致，未覆盖已有文件。证据位于 `results/tsc_revision_r2/margin_smoke_v1/`。本轮没有获准编译输出，因此不是新样本零退化或有用覆盖率的证据。下一步在 12 个开发来源上选择门禁、事前成本估计与单次档位，再用已冻结的 50 个新来源测试。
