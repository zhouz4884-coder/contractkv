# 第二阶段：实际长输出、格式指令与原生模板条件

三个模型均已出现“实际 >512 tokens、自然 EOS、认证获准、后续 raw/compiled 数组正确且无任务分数下降”的完整条件。下表每行包含三个独立服务重复、6 个未来配对；不是由输出 cap 推断长度。

| 模型 | 实际条件 | 请求内容量 | 返回 tokens（含终止 token） | 获准参考 | 未来 raw 正确 | 未来 compiled 正确 |
|---|---|---:|---:|---:|---:|---:|
| Qwen3-8B | 显式 schema + 原生 `enable_thinking=False` | 128 个整数 | 642 | 3/3 | 6/6 | 6/6 |
| Mistral-7B | 显式 schema | 128 个整数 | 769 | 3/3 | 6/6 | 6/6 |
| Llama-3.1-8B | 显式 schema，独立声明的更长内容 | 192 个整数 | 578 | 3/3 | 6/6 | 6/6 |

这是同一 JSON 整数数组任务族的分条件证据。Llama 使用更多内容以达到实际长度要求，不能把本表说成三个模型使用相同 128 项输入都输出 >512 tokens。每个条件内 raw 与 compiled 的任务内容、格式指令、预算、解码和模型相同，候选按固定规则调整稳定内容与私有元数据的次序。完整条件、包括失败和更长输出，均保存在原始记录与 CSV 中。

本轮依次完成 V2 三模型 9 cells/180 次实际生成/72 个未来配对，Qwen 原生模板 V3 的 3 cells/60 次生成/24 个配对，以及 Llama 更长内容 V4 的 3 cells/60 次生成/24 个配对。所有条件保持 raw/candidate 最小 margin 0.0625，包含自然 EOS 检查；没有为长输出放宽门槛。控制实验直接测资格验证与复用，不进入正式服务经济门禁的吞吐或 p99 分母。

Qwen 的模型模板需要独立说明。V2 的 `/no_think` 指令仍产生空 `<think>` 包装；原来的 128 项评分器会剥离它，因此任务分数正确，原始响应不符合纯 JSON 形式。V3 在显式 schema 条件中使用模型模板已有的 `enable_thinking=False`，并一致用于真实生成、candidate 与 prefix 的 `/tokenize`。这是单独声明的模型原生模式条件，保留默认模式对照。它没有改写生成结果、模型权重、注意力内核或评分器，也没有使用 guided decoding。每次实际请求的模板选项及 prompt/output hashes 有独立日志。

Mistral 的默认 128 项条件中，6 个未来 raw 输出均未满足整数序列谓词，compiled 输出均正确；默认 160 项有 3/6 raw 失败。显式 schema 条件下，两种内容量的未来 raw/compiled 都为 6/6 正确，实际分别达到 769/961 tokens。格式指令同时改善了 raw 生成的稳定性；这种改善不能全部算作 ContractKV 的贡献。

Llama 的 V2 显式 schema 已修正 `[JSON_ARRAY]` 包装，并获准复用，但 128/160 项输出变成紧凑 JSON，实际只有 386/482 tokens。它们不是 >512 的成功条件。随后在生成前冻结 192/224 项的独立内容任务，保留原来的 128/160 项结果与评分。192 项达到 578 tokens，三个参考和 6 个未来 raw/compiled 配对均正确。

224 项压力条件没有成功。三个重复都把终点 1224 生成成了 1124，仅输出 124 项：显式条件为合法 JSON，但缺少 1125–1224 这 100 项，实际 374 tokens，候选拒绝且无发布。默认指令还带有包装，实际 501 tokens，错误 raw 参考的行为路径可以获准。认证以 raw 行为为参照，绝对任务正确性由独立评分检查；这两个指标必须分列。已有证据支持“基座模型端点跟随错误”的解释，未证实其内部成因，也没有通过改变评分或补齐输出掩盖错误。

冻结的 128 项 `score()` 保持原样。160/192/224 是另外声明的内容条件，其完整序列、整数类型及数量检查另列。原日志名为 `strict_plain_json_integer_sequence` 的字段会剥离模型 think 标签；补充审计明确区分了该规范化答案谓词与直接解析原始响应的谓词，没有改写冻结日志。所有实际 prompt IDs、SHA256、输出 IDs、usage、验证请求、缓存命中、原生模板选项和拒绝后的零发布均通过复核。

本组使用完整自然停止的长 witness 进行验证；它不证明前 64/96 个 token 的认证足以覆盖任意更长答案。未来输出与 witness 的首次分歧和超长位置有独立列。它也是受控机制审计，真实 QA/代码任务的质量与端到端服务效果由独立工作负载矩阵报告。
