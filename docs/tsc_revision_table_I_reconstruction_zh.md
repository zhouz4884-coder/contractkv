# Table I：以实际输入与命中账本重建的统计

日期：2026-10-16。以下是**新定义、可复算的受控统计**，不宣称恢复了原 85.0/2.4 或 82.4/2.1 的来源。

## 定义与数据

先完成同四来源 Qwen 开发对照的 raw 路径重建：旧输入和保真输入各 400 个业务请求，其中各有 360 个未来请求、40 个 tenant turn-zero 业务请求；基础设施前测不计入。四来源、模型和任务问题保持对应，输入预算与显示片段结构不同。

每条请求均重建完整 chat template，核对 tokenizer IDs 与服务端实际记录完全一致。根据原始 segment 顺序和类型定位正文字符范围，再映射实际 token offsets。

稳定正文定义为声明 `cache_stability=1` 的 segment 内容，排除 query、observation、history、scratch、注入标题、外层 chat 控制/系统包装及跨正文边界的 token。它是 manifest 声明下的统计，不证明内容可公开。分母为全部实际 Prompt IDs，包含标题和 special tokens。

原生总命中占比使用实际 prefix-hit tokens / 全部 Prompt tokens。稳定正文恢复率则只数命中前缀内被标为稳定正文的位置，再除以稳定正文 tokens。两者不是同一个指标。

## 首批结果：未来请求、token 加权

| 统计 | 旧输入 | 保真输入 |
| --- | ---: | ---: |
| 未来请求 | 360 | 360 |
| 全部 Prompt tokens | 1,514,970 | 3,198,060 |
| 稳定正文 tokens | 1,386,540 | 3,144,060 |
| 稳定正文 / 全部输入 | 91.5226% | 98.3115% |
| 原生前缀总命中 tokens | 34,560 | 34,560 |
| 原生总命中 / 全部输入 | 2.2812% | 1.0807% |
| 其中属于稳定正文的命中 tokens | 1,080 | 1,080 |
| 稳定正文命中 / 稳定正文 | 0.0779% | 0.0344% |
| 稳定正文命中 / 全部输入 | 0.0713% | 0.0338% |

按来源先求 token 比例、再作等权平均，稳定正文占比分别为 89.7548% 和 97.7858%。不能把来源宏平均与 pooled token 比例混写成一个数。

| 条件 / 家族 | 来源数 / 请求数 | 稳定正文占比 | 原生总命中占输入 | 稳定正文恢复率 |

这说明在该受控顺序中，很多声明稳定的正文位于动态段落之后，无法由原生连续前缀命中恢复。它不证明所有真实应用都有相同占比，也没有生产频率的含义。旧 HotpotQA 的原生总命中占比本身高于 3%，因此不能预设“每个家族都低于 3%”。

完整 JSON 同时保存 warm/future/all-business、各家族、按来源宏平均与 token 加权结果，以及每个模型/来源首个实际 Prompt IDs、segment 顺序/类型和字符跨度。逐请求 CSV 保存实际 IDs 哈希、请求定位与真实命中量；其完整 IDs 来自已归档原始服务日志。

## 解释限制

- 保真协议同时恢复更多正文并减少内部 chunk 标题；不能将比例变化只归于词数预算或标题移除中的一个。
- Native 总命中包含控制/系统等 token，不等于稳定正文恢复。本文保守地不把外层包装计入注册稳定正文。
- 这四个来源属于开发数据；三个模型的新六来源独立结果完成后另加统计，不替换本表。
- 原稿具体数值仍缺原始来源链；不能称为某次“早期快照”，也不把本表称作这些数值的复现。

源码：`scripts/tsc_revision_r4_table_I_reconstruction_v1.py`。结果：`results/tsc_revision_r4/table_I_reconstruction_{head,faithful}_DEV_v1.json/.csv`。实际 IDs 逐条核对是本次重建的前置条件，CPU 分析没有新模型请求。
