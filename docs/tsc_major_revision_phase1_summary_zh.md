# ContractKV 大修补强第一阶段总报告

日期：2026-10-15。第一阶段实验、原始证据归档及本地复核已完成。七项补强都有对应结果；其中部分结果支持原有机制，部分要求收紧论文结论。原投稿稿件和逐点回复尚未修改，不能把实验完成等同于可以立即提交修回稿。

## 完成范围与方法

| 实验组 | 完成量 | 方法和用途 |
|---|---:|---|
| 原 R1 七项补强 | 78 个 live 单元，25,650 次未来请求 | 三模型共同 HotpotQA、五任务族自由生成、原预算/512 条件、零 slack 服务、14B TP2、D1/D2 与其他审计 |
| query 绑定正式补测 | 45 个单元，28,350 次未来生成 | 三模型、五任务族、三次新进程重复；冷 session 与十 tenant 模板分别测量 |
| 实际长输出 | 9 个单元，135 次真实生成 | 27 次 raw 参考、108 次 raw/policy 未来生成；256/512/1536 三种上限 |
| 原失败案例定向对照 | 9 个策略单元，108 次未来生成 | 四个已知模型/来源单位；相同新 backend 上比较 raw、旧作用域逻辑和新 query-prefix |

新增方案在 exact query 首次出现时先提供 raw 业务回答，以该真实输出作认证见证；后续仅复用相应 query 获准的布局。验证可读取此前获准且仍驻留的稳定前缀，只提取答案与 EOS 所需的 logprob 行。Transformer/KV 计算和业务生成均真实执行。

这是受控修复变体：沿继承最大级别向下尝试，辅助 margin/degradation 阈值使用宽界，未执行原投稿完整收益门禁。`query-full` 表示全上下文验证计算；新结果不能替换原投稿完整策略的主表。

## 七项补强的结果

| 补强项 | 数据结论 | 对论文的意义与边界 |
|---|---|---|
| 非 RULER 共同跨模型 | 相同 30 个 HotpotQA sessions，共 2,430 配对；新 prefill 降低 38.38–48.05%，无 >0.03 的分数下降 | 支持收益不只存在于 RULER。零 slack 宏均值改善 5.24%，95% CI [-2.16,12.56]%，不支持所有冷会话普遍获益 |
| 认证后自由生成 | 原 R1 有 108/3,672 个已编译配对退化；新正式样本 8,595 个编译配对中仍有 2 个退化 | 原 changed-query 问题需要收紧作用域；修复已有直接对照支持，但尚未形成任意未来输入的行为保证。两批来源/策略不同，不能据此计算因果风险降幅 |
| 较长输出 | Qwen 六个编译未来输出均为 646 tokens，正确且与未来 raw IDs 一致；Mistral 六个为 769 tokens，格式评分正确、与未来 raw 不同；Llama 517-token 输出格式失败且认证拒绝 | 建立两模型真实 >512-token 的受控机制证据。不能把上限或 raw 输出长度算作获准长输出，也不能声称所有模型与 raw 逐 token 相同 |
| 完整成本与零 slack | 原四配置新测全成本净 TTFT 改善为 Qwen 17.50%、Mistral -2.84%、Llama 7.69%、14B TP2 10.59%；真实零 slack 服务中 Qwen 1500ms goodput 0.425→1.307 req/s，Mistral 0.010→0.011 req/s | 强收益具有任务和复用条件；Mistral 冷会话成本仍需优化。历史缺失的参考/失败时钟继续标为不可得 |
| D1/D2 安全消融 | 两组各 20 个控制案例：各自 10/10 真正坏布局被拒绝，拒绝发布均为 0；14B 补测真实后决策输出保持 raw 分数 | 支持 D2 对坏布局的准入和发布治理价值；D1 无在线认证，仍是更快的已知安全布局参考 |
| manifest 与隔离 | 9 个独立 CPU 注册检查符合预期；正确签名的可信运营者错误私有声明仍会被接受；live scope/namespace/policy 控制单独通过 | 哈希验证身份，不能判断内容是否应当私有。CPU helper 未接入 live endpoint，无时延侧信道防御结论 |
| CacheBlend、统计和输入布局 | 9,000 个 native-matched 配对、阈值敏感性、4,695 个 segment 位移及来源簇 CI 已完成 | 保留 CacheBlend 均值改善与个别退化并存的事实；不作 2.18% 跨运行栈因果性能优势或 112 倍因果安全排名；受控输入不代表生产重复 query 的频率 |

## 新方案的实际服务收益

以下十 tenant 模板场景使用十个固定来源模板、每模板十个 tenant，实际并发为 2。完整 wall 计入首次 raw、warm 业务、失败验证、准备与等待，不减去假想工具等待。它是闭环重放，不能视为 100 并发或开放环容量结果。

| 模型 | 质量配对 / 编译 | 全成本吞吐 raw→新方案 req/s | 吞吐倍率 | wave-ready TTFT 均值改善 | 编译退化 >0.03 |
|---|---:|---:|---:|---:|---:|
| Qwen3-8B | 2700 / 2232 | 1.140→2.407 | 2.111× | 69.43% | 0 |
| Mistral-7B | 2700 / 1374 | 0.763→0.905 | 1.185× | 26.83% | 1 |
| Llama-3.1-8B | 2700 / 1374 | 0.962→1.149 | 1.195× | 26.98% | 1 |

三个模型的来源簇 TTFT 改善 95% CI 分别为 [47.91,84.63]%、[11.09,48.00]% 和 [10.80,47.94]%。但 wave-ready p99 均变差：Qwen 1894→2901 ms、Mistral 2330→2352 ms、Llama 1814→1893 ms。平均收益不能替代尾延迟结论。readiness 从两请求 wave 屏障计时，不是各 tenant 独立就绪时刻。

单 session 场景的全成本吞吐倍率分别仅为 1.034、1.002、0.997，TTFT 均值改善 CI 均跨 0。前缀辅助验证的累计调用成本比全上下文检查低约 33–40%，但这没有自动转化为冷会话端到端收益；重叠调用的时间也不能再次加到已测 wall 上。

## 原失败的修复对照与残余问题

四个原失败单位均在旧作用域逻辑控制下再次出现分数退化，新组合方案在相同未来请求中保持 raw 输出。这是已知失败的定向诊断，选样发生在发现问题之后；三策略固定顺序且共享新进程，不是原运行栈或批形状的完整复现，也不用于性能比较。

| 已知失败单位 | 旧控制退化配对 / 9 | 新方案退化配对 / 9 | 新方案实际编译 / 9 |
|---|---:|---:|---:|
| Llama / NarrativeQA doc126 | 3 | 0 | 5 |
| Mistral / NarrativeQA doc85 | 3 | 0 | 5 |
| Qwen / Qasper doc189 | 6 | 0 | 7 |
| Qwen / RepoBench MergeMonster | 6 | 0 | 7 |

新正式矩阵中的两例仍保留：Mistral 的 raw 分数在三次重复中变化，编译输出与原见证相同；Llama 的三个 raw 对照分数和 token IDs 都稳定，新编译输出却退化。后者不能用 raw 波动解释，其资格化请求读取已批准前缀的 token 数为 0，因此也不能直接归咎于前缀读取。三次认证选择的级别和首次见证不同，尚未完成同候选、同 prompt 的因果分离。

长输出的 Llama 错误表现为额外 `[JSON_ARRAY]` 标记，Mistral 未来 raw 错误表现为整数被输出为字符串。这些是观测后的格式分类；冻结主评分保持原样，格式失败与 token/EOS 认证拒绝独立判定。

原 R1 有 216/3,672 个已编译自由输出超过自身实际见证长度，总计 2,376 个额外返回位置；这些位置没有被标为已认证。新矩阵逐项记录了全部 8,595 个编译输出的真实见证 IDs。Teacher-forced rank-one membership 允许并列最大值，不构成任意后续生成的逐请求数学保证。

## 可复现性与交付核验

- 原 R1 423 个、R1R 主包 534 个、已知案例包 72 个归档成员均逐项通过字节哈希检查；三份完整归档 SHA256 见各自 manifest。
- 主包 5 个、案例包 1 个 GitHub 大小适配分卷已核验；恢复过程没有覆盖已有文件。
- 本地重跑主矩阵、长输出、已知案例及加强身份/指标审计均通过；重新生成的主/长输出 CSV 与远端字节一致，JSON 解析值一致。
- 83 项运行前承诺的源码/输入及快照哈希在最终远端检查中全部匹配；63 个非测试结果代码文件与 native 扩展信息已留存。
- 40 项针对性 CPU 检查通过。它们检验审计和实现基础，不能替代 GPU 实验结果。
- 远端本任务 GPU 进程已全部退出。最终清理检查没有停止任何进程；两张 3090 当时各占用 24 MiB。

归档哈希证明传输与来源一致，不证明科学目标全部达到。R1R 没有逐请求记录完整 prompt token IDs/hash，输入一致性依据冻结来源、session/turn、确定性 renderer 和模型配置；第二阶段的严格机制控制需要补齐这层记录。

完整表格见 [新增实验报告](tsc_major_revision_r1r_results_zh.md)、[原 R1 报告](tsc_major_revision_r1_results.md)、[审稿意见证据表](tsc_major_revision_r1_review_tracker.md)与[复现说明](tsc_revision_r1r_reproduce.md)。本地审计总记录为 `results/tsc_revision_r1r/local_completion_audit_v1.json`；远端清理及哈希检查为同目录的 `remote_closure_v1.json` 和 `closure_freeze_audit_v1.json`。

## 第二阶段的执行入口

第一阶段报告交付之后，再开始以下优化：先用 Llama 反例固定完整 prompt IDs、候选级别、设备及批形状，对比通用完整 logprob、内部行提取验证和真实自由生成，区分输入作用域、数值轨迹与实现问题；再在开发数据上选择修复，并冻结新样本验证。冷会话优化检查首次 witness/失败尝试成本和收益门禁，长输出优化另设更明确的格式指令条件。

原 R1/R1R 协议、分数、失败和分母继续保留。第二阶段的成功标准是同等任务质量约束下改善实际全成本指标，并在未用于选择修复的新数据上复核；仅修好这些已知例子不足以宣称普遍安全。
