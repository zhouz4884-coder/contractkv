两张3090的168次模型请求全部完成：108次自由生成、48次完整 teacher-forced logprob、12次内部资格验证。独立审计确认全部请求的实际完整 prompt IDs、输出 IDs、usage、官方任务评分、metrics 与实际 ModelRunner 采样轨迹一致。两个 GPU 都记录到了实际 active requests 为1和2的执行。

## 实际复现

raw/candidate、t1/t7 四种输入都与三个历史重复中的实际 prompt IDs 完全相同，每个 prompt 为2803 tokens。t1→t7只改 TOOL_OBS 的轮次编号，任务证据和 query 不变。自由生成结果在两个GPU、单请求/双HTTP请求、冷缓存/认证后热缓存中保持以下模式：

| 布局与输入 | 自由生成 F1 | 同一 t1 参考 token 在分歧位置24的 full logprob rank/margin |
|---|---:|---|
| raw t1 | 0.071429 | rank1，+0.125 |
| raw t7 | 0.121212 | rank2，−0.0625 |
| candidate t1 | 0.071429 | rank1，+1.125 |
| candidate t7 | 0.071429 | rank1，+0.96875至+1.0 |

位置24从0计数。raw t7稳定改用更长的“信息不足”表述，candidate 则逐 token 保持 t1参考。teacher-forced raw t7在该位置已不把参考词排为第一，与自然生成改变方向一致；candidate 对参考词仍有明确正 margin。这组结果支持元数据取值与布局交互改变输出轨迹，不支持把本例简单归因于 candidate 的近并列、缓存读取错误或内部行提取单独误判。

12次内部验证均获准。认证后的36次热生成都有真实 prefix hits，范围2720–2800 tokens；所有唯一 salt 的冷对照均为0 hit。热路径与相同输入冷 candidate 的36个输出 ID 对照全部一致。72个 candidate/raw 配对中有36次 >0.03下降，全部在 t7，冷/热各18次；都是同一个已知来源的相关重复，不能当作36个独立来源的风险样本。

## 方法含义与边界

认证维持 witness 的行为，与“维持未来 raw 的词面分数”是不同要求。提高 candidate margin 门槛无法直接排除该例：candidate 在相同参考路径上仍稳定选择原表述，变化在未来 raw 的参考轨迹。下一步应限制跨动态元数据的适用范围，而不是用一个恰好卡住旧样本的新阈值宣称修复。

本控制在指定设备、版本、输入和执行条件下复现了上述模式，并不证明其他请求没有 batch/浮点敏感性。完整 logprob与内部行提取的数值差异及实际执行形状均保留；没有声称所有条件使用完全相同的 GPU 张量形状。

同时测试中的开发作用域原型只限制准入，不改写已生成答案，不读取 gold 标签。它还没有在新50来源上运行，不能用本组已知控制或CPU规则重放代替新策略质量验证。
