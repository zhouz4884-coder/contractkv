# 第二阶段：并发 tenant 机制控制

本轮沿用前一轮冷/复用驱动，每次 chat 调用同时提交相邻 tenant 的请求，只改变其受控 metadata 字段；冷 twin 使用独立 salt，复用 twin 使用同一资格化 salt。两个完整响应均保留。三次重复交换冷/复用顺序，模型权重、后端与准入阈值未变。

| 模型 | 自由生成 / 资格化 / 实际指标关联 | L2 获准 | 主请求冷/复用 token 差异 | 主请求退化 >0.03 冷/复用 |
|---|---:|---:|---:|---:|
| Llama | 42 / 3 / 45 | 0/3 | 0/6 | 0/0 |
| Mistral | 42 / 3 / 45 | 3/3 | 0/6 | 3/3 |

Mistral 的冷与复用退化指同三个未来输入，不能算作六个独立失败；相邻 tenant 对照没有阈值退化。所有 HTTP 配对时间区间重叠，服务器实际观测到两个活动请求。这不等于已经逐步记录每个 GPU kernel 的 batch shape，也不是原长业务轨迹的完整重放。

Llama 的并发 raw 见证变为较短表述，F1 仍为 0.210526；L2 三次均被拒绝，没有已获准复用正例。不能把这些手动候选生成解释为获准服务。Mistral 见证仍为 0.066667，而未来主请求 raw 分数为 0.142857；冷与复用候选都维持较低分数。因此问题并非 KV 复用独有，不能通过只修缓存读取来闭合这个反例。

进一步检查已有真实 raw margin 向量：Llama 单请求见证的 raw q05 为 0.103125，但最小答案 margin 为 0；Mistral 的最小 raw 答案 margin 为 0.03125。Llama 并发见证的最小 raw margin 为 0.015625。API 返回精度下的这些小间隔说明 q05 无法代表所有位置的稳定性，但不能单凭它们证明浮点误差是唯一原因。

下一项开发改动将评估逐 token 最小 margin 硬门禁；候选阈值及选择规则在开发测量前冻结，最终还需新的来源不重叠样本。按用户补充建议，服务路径同时评估事前收益估计与最多一次验证，明确计入控制器及 token 准备开销。尾延迟能否回落由真实 ready TTFT/p99 决定，不把跳过验证描述成总开销绝对为零。长输出另设显式格式指令条件，原评分器不变，格式正确与认证通过分别检查。

90/90 个请求身份、完整 prompt/output IDs、冻结评分、真实指标和并发观测核验通过。33 个冻结文件与原有 83 项承诺匹配，65 个原始归档成员逐项哈希通过，本地重算 CSV 字节和 JSON 值一致，无恢复覆盖。证据位于 `results/tsc_revision_r2/batch_reuse_v1/`。这些结果属于已知失败的开发诊断，第二阶段实际优化和独立验证仍未完成。
