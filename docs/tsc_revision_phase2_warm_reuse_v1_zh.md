# 第二阶段：认证 KV 复用控制

本开发控制沿用第一阶段后端和宽辅助阈值。两个已知案例各使用一个新进程、固定 GPU，串行请求、进程内三次重复。先用真实 raw 见证资格化 L2，再在同一资格化 salt 下生成，和独立冷 salt 的相同 prompt 比较。第二次重复交换冷/复用的执行顺序。

42 次自由生成和 6 次资格化请求全部成功并关联到实际指标。每模型六组冷/复用比较均获准并实际命中前缀，prompt IDs 完全一致；冷控制和资格化的 prefix read 为零。两模型各六组均没有冷/复用 token 分歧，也没有 >0.03 的分数下降。这个控制没有重现原退化，不能算作已修复。

结果排除了“单独开启该串行复用条件必然造成已知错误”的解释，没有排除并发调度或跨形状的数值影响。下一轮在同样的 raw/冷/获准前缀条件下加入第二个真实 tenant 的并发请求，记录两个响应及实际调度观测。所有已观察结果继续保留，不改变第一阶段阈值。

32 个冻结源码/输入文件匹配，原有 83 项承诺文件在收尾复核中仍匹配。57 个归档成员逐项哈希通过，本地复算与远端 CSV 字节及 JSON 值一致，恢复没有覆盖。两项针对性 CPU 检查验证同 salt 不等于实际命中，以及 prompt 变化不能归因于 cache 状态；它们不是 GPU 效能结果。

证据位于 `results/tsc_revision_r2/warm_reuse_v1/`。这是选择已知失败后的机制控制，不属于独立 held-out 质量、性能或普遍安全证据。第二阶段的实际修复、冷会话收益门禁、长输出格式和新样本验证尚未完成。
