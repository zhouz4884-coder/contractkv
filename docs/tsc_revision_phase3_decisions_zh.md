# 第三阶段：假设、证据与决策记录

第三阶段优先解决 Qwen 新反例、收益门禁没有实际筛除与 p99 偏高。先诊断、再开发选择、最后冻结新策略并验证；保留全部结果，最终统一汇报。用户补充方案是候选假设，不是已经证明的因果结论。R4 是本阶段的实验版本号。

## 启动时的判断

1. Qwen doc99 的 t1/t7 任务证据不变，实际渲染文本只改 observation 的轮次编号（1→7），query scope 相同。raw 首次输出分歧位置 24 的 witness margin 是 0.09375/0.125/0.125，而 candidate 最小 margin 是 0.40625。需要区分元数据敏感性、数值执行和跨动态输入复用；不能直接称为新知识改变答案。
2. 1188 个计划全部放行是事实；305 次拒绝发生在全部 1019 次认证中，不全属于冷会话。失败成本、raw logprob 与计划成本、通过后实际边际收益都需计入预测。它们与 p99 的关联尚不等于唯一因果解释。
3. 已观察 Mistral/Llama 尾部多为固定 L0 的 RepoBench。把其他请求耗时设为零得到的是“保持这些已观察 L0 延迟不变”的算术控制，不是不可改变的硬件物理下限。全局和预先定义的家族分层一起报告。
4. 置信区间跨零不能仅归因于 wave 屏障。移除屏障必须实际更改调度，并让 raw 与新策略采用同一到达/调度协议；不能通过改计时起点制造改善。后台认证仍占 GPU，等待与收尾都计入完整 wall。
5. CPU 早退不等于零毫秒成本，预测延迟上限也不是硬实时保证。192 项成功不是已证明的 Llama 能力上限；224 项锚定指令与在线 manifest 是次要候选，主任务优先。

## 预定证据链

- 使用 R3 封存原始记录做离线逐 scope 成本/通过率/复用分析，原始逐请求差异和算术反事实只作为诊断，不冒充线上收益。
- 在两张 3090 上对已知 Qwen 来源做相同 prompt IDs、两种布局、冷/认证后热缓存、单请求/并发执行控制。保存实际执行形状与完整 IDs，不能把 HTTP 同时提交等同于 GPU 相同 batch。
- 在已观察数据上开发失败概率折算、完整成本和延迟预算门禁；对动态作用域给出可审计条件。资格收紧导致的覆盖减少单列。保持评分和所有旧策略源码/日志不变。
- 提前冻结另 50 个来源（每族10个），排除全部462个既往来源，seed10672131；十租户子集按每族前两个固定。选择不读取模型输出/分数。任何正式新结果不再用于本版调参；如需修正，另立版本与新验证。
- 正式比较保留 raw、上一版受控策略和新策略的匹配条件。必要的独立请求调度条件另外声明，不能把旧 wave 的指标与新协议直接相减当作纯算法收益。
