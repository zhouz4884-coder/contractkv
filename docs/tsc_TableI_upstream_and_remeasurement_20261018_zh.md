$\rho_s=\sum stable\ body\ tokens/\sum actual\ prompt\ tokens$。

$\rho_p=\sum stable\ body\ tokens\ within\ actual\ cached\ prefix/\sum stable\ body\ tokens$。

另列 $\rho_h=\sum all\ cached\ tokens/\sum prompt\ tokens$。历史、问题及聊天框架不算稳定正文；跨字符边界的 token 不强行归入稳定正文。所有归属用完整 chat rendering 的 token offsets 对齐，GPU 返回的 Prompt IDs 还要逐项核对。

该协议测的是**有来源依据的受控服务输入**，不是生产查询频率或自然对话总体分布，也不证明编译质量等价或系统加速。

## 6. 关于保留原表角色与跨模型补充的决定

用户希望保护 Reviewer 1 对研究动机的认可，并提出：若新测量与旧结果同量级，是否可不改旧表，另加六来源、三模型证据。

本轮采用的区分是：可以保留 Table I 的论证位置、结构性缺口命题及表格角色；新结果若支持该观察，可以明确报告“独立测量支持同一结构性问题”。但量级相近不能认证旧五行的生成过程，不能将不明来源的旧点估计称作已恢复原测量。

六来源、三模型证据可形成独立面板或配套表。该组每模型 6 个来源、1,620 个未来 raw 请求，稳定正文占 98.357%–98.520%，稳定正文的原生恢复为 0.030%–0.034%；所有 token 的原生命中占比则为 0.950%–1.114%。三者分母不同，不能把最后一列换称为 stable recovery，也不能同新五家族/增长历史协议合并为一个共同均值。

最终表格组织应以实际新结果为准，明确两组 cohort、窗口、历史规则和统计分母；不根据是否接近旧点估计选择呈现哪一组。

两组可共用一张表的独立分面，也可采用主表和补表；稳定正文的登记范围、系统框架 token 的归属也应各自明确，不能无声混算。

另设最终完整性核查：逐请求检查历史是否来自真实先前答复、稳定正文是否保持相同，并完整报告十轮描述统计和离线无限驻留前缀上界。该核查在运行期间、最终结果聚合前加入，独立于事前冻结的主估计器；不改变提示、选样或生成条件，也不用于挑选最接近旧表的某一轮。

## 7. 运行中发现的记录 ID / 原文来源区别

与已排除历史记录的原文哈希核对后，NarrativeQA 的 25 条新记录、Qasper 的 5 条新记录的上下文此前已出现。新记录 ID 不重叠不等于文档未见。已有六来源仍有六个不同原文，且与本轮上下文无重叠。

决定：不删记录、不补新来源、不重跑挑选更好数据；完整执行已冻结矩阵，保留原登记的点估计和 ID 簇区间，额外按原始上下文整簇给出区间。映射和统计规则于运行期间、主结果汇总前记录在 `context_cluster_addendum_v1.json`。本轮用于结构性动机的重新测量，不宣称未见文档上的算法泛化验证。此前“125 个独立来源”的称呼据此纠正。
