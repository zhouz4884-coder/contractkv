# 第二阶段：开发集档位与成本标定

本轮完成开发集采样、独立审计和策略冻结，尚不构成独立新样本上的优化成功证据。

使用预先冻结的 12 个开发来源，包含两个已知反例来源。每个可用来源覆盖三个 query、两个 metadata/tenant 条件和两个未来轮次。各档位是独立开发控制，线上策略不会沿这些档位连续重试。Mistral 与 Llama 的 Qasper、RepoBench 继续使用原先固定的 L0。

| 模型 | 实际生成 | 独立验证调用 | 获准验证 | 获准后候选未来生成 | 候选相对同输入 raw 的 >0.03 分数下降 |
|---|---:|---:|---:|---:|---:|
| Qwen3-8B | 556 | 108 | 85 | 340 | 0 |
| Mistral-7B | 300 | 72 | 39 | 156 | 0 |
| Llama-3.1-8B | 304 | 54 | 40 | 160 | 0 |
| 合计 | 1160 | 234 | 164 | 656 | 0 |

以上 656 次候选生成均发生在相应档位获准之后，并核验了实际 certified prefix hit。被拒绝档位没有生成候选未来输出，不能将这些缺失输出称为已经执行过的 raw fallback。该轮关闭 pointwise 下限以采集候选最小 margin，保留路径一致性检查。它也没有复现第一阶段的两个编译退化案例；因此，不能仅凭本表说新门槛修复了所有历史失败。

全部 1394 个测量请求（生成加验证）的实际 request ID、完整 prompt token IDs、SHA256、usage 与服务端缓存指标匹配；官方任务评分重新计算一致。失败验证发布 token 数为 0。运行前冻结 63 个源码、配置、输入及依赖文件，源码快照和当前字节通过检查。模型检查关联三个模型的完整 checkpoint 注册表；每 cell 检查权重文件大小、mtime，并重算 tokenizer、配置和索引的 SHA256，未将历史未记录的完整权重哈希补写成旧证据。

开发选择只使用此前冻结的网格和规则：正的 raw/candidate floor、保守 p95 验证成本、原生 raw prefix 命中折扣，以及预先声明的 1/10 租户复用提示。单个失败尝试也要扣成本。全模型、任务族等权；开发集出现 >0.03 候选分数下降的选择不能进入最终配置。零下限只作为控制，不能部署。

选中 raw 全输出（含 EOS）最小 margin 0.03125，candidate answer 与 EOS 下限 0.0625，收益安全系数 1.0。Qwen 五个任务族选 L3；Mistral 和 Llama 的 RULER 选 L3、HotpotQA/NarrativeQA 选 L2，另外两个任务族为 L0。完整网格与每个成本系数见 `results/tsc_revision_r2/profile_v1/analysis`，部署配置为 `configs/tsc_revision_r2_selected_catalog_v1.json`。

收益预测使用 raw-future TTFT / 实际新增 prefill token 数的中位数，属于延迟预测器，不是纯 GPU prefill 计时。预测目标没有单独估计请求 logprob 的额外开销，不能作为端到端加速数字。声明的剩余复用次数也不是实际未来结果的 oracle。真正的质量、冷会话完整收益和 p99，必须由随后完整服务试跑及独立新 50 来源验证给出。这里没有声称新样本零退化、冷会话转正或 p99 已降低。

原始证据包有 106 个成员，SHA256 为 `7c5fe0305c025d96ba33c06c3b529aff5aa902372dba8664ea93420ae8ec03df`。本地重组后逐成员哈希验证通过，独立重算的所有 CSV 和 JSON 与远端分析一致。预热控制单独保存并排除在业务和成本标定分母之外；旧预热控制的日志粒度不等同于本轮测量请求的完整 IDs 日志。
