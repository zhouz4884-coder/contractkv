## D02：成本适配先查代价与收益两侧

**依据：** 旧短输入校准低估了部分约 4.1 秒认证；当前代码也可能用旧 prefill reduction 分位数限制长输入收益。只把成本乘长度比可能同时过度拒绝合法复用。

**决定：** 仅用已经观察过的开发日志做 CPU 审计，分模型、长度、候选级别、已记录前缀状态和可观察执行形状；同时检查成本预测、可节省工作和失败浪费。暂不写死线性公式，不增加预测网络或异步调度器。

**约束：** 独立 18 单元的任何输出都不用于选择成本参数。若开发证据不足，保留负结果；必要的成本适配须单独声明、冻结、有限 A/B，并和原版保真 R4 区分。

## D03：发布身份不是完整物理驻留证明

**依据：** 开发对照有四次 3728/6768 tokens 的部分前缀命中；现有控制器记录的是已发布 hash，缺少逐块驱逐证明。

**决定：** CPU 审计把“观察到发布”“曾命中”“当前完整驻留未知”分开。成本适配不得把前者改称后者；无法确认时可考虑保守成本，但不先认定驱逐是唯一原因。
