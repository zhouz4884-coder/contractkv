# 第三阶段启动诊断：哪些解释有证据支持

本记录只使用第二阶段封存数据，没有新增推理请求，不是第三阶段独立效果结果。输入文件均与完成审计中的 raw SHA256 核对。逐 scope 数据位于 `results/tsc_revision_r4/prior_diagnosis_v1/`。

Qwen doc99 的 t1/t7 查询相同，渲染的任务证据相同，只有 TOOL_OBS 的 `turn=1` 变为 `turn=7`，status 都是 completed。完整原始 prompt 长度均为 2803 tokens，四种 raw/candidate、t1/t7 几何在三个历史重复中一致。raw 输出首次分歧的位置 24 恰是参考的最小 margin 位置，其 margin 为 0.09375/0.125/0.125；candidate 参考轨迹最小 margin 则为 0.40625。不能把这件事解释成 observation 新增了答案证据，也不能仅依据高 candidate margin 推导未来 raw 轨迹不变。

因此安排已知来源控制：两个 GPU，raw/candidate 两种布局，t1/t7 两个精确历史输入，唯一 salt 冷路径与真实获准后的相同 salt 热路径，单请求/双 HTTP 请求条件，各三个同服务进程重复。完整 logprob 对相同实际 t1 witness 做四种 prompt 的 teacher forcing；实际 ModelRunner trace 单列，不把 HTTP 并发标签冒充固定 GPU batch。两张卡共 168 次模型请求；这是已观察失败的诊断，不是未见样本成功率。

成本侧确认：1188 个计划全部放行，真正尝试 1019 次、获准714次。305次拒绝来自两个会话条件，不能全部算作冷会话。冷会话中，Mistral 的 HotpotQA/NarrativeQA 认证通过率约 47.6%/50.0%，Llama 约 50.0%/43.5%，Qwen HotpotQA/NarrativeQA 约 64.0%/52.0%。这些是相关重复下的描述频率，不是独立 Bernoulli 风险保证。

通过后的 backend TTFT 平均差异约为：Mistral HotpotQA/NarrativeQA 476/612 ms，Llama 507/587 ms；对应完整资格 p95 却约为 Mistral 1602/1830 ms、Llama1493/1525 ms。两次左右的复用乘上通过概率，未必能摊平成本。RULER 的通过率较高，但冷会话完整资格 p95 也高于原开发目录中的成本。旧公式还以 raw TTFT/新 prefill token 的均值近似边际可节约成本，需与实际匹配的缓存收益重新校准。

raw logprob 采集、候选规划、失败认证和实际复用必须一起核算。逐 scope 的 backend 差异只能指导开发模型，不能取代包含并发等待的完整 wall 测量；不能把重叠请求耗时相加后当作服务时长。

尾部的“固定 L0 下限”已做条件算术控制：保持固定 L0 请求的已观察延迟不变，把其他请求设为0，再计算全局 p99。这能解释为何编译家族变快未必改变总体尾部，但它不是硬件不可改变的物理界限。新实验将保留全局、固定 L0 家族和预先允许编译家族的分层，避免只挑实际获准请求报告。

运行环境重新验证通过：两张 RTX3090，torch2.8.0+cu128、vLLM0.10.2、transformers4.55.2、triton3.4.0。三个模型全部权重重新哈希，与第二阶段注册身份一致；旧729项源码/快照、6项执行补充和原始83项承诺复核通过。新50来源在任何第三阶段 forward前选定，排除462个既往来源。首次本地选择因三个旧排除文件缺失在写输出前失败，随后在持有全部文件的已核验远端完成，未放松排除或哈希要求。

开发优化优先验证：失败概率折算的完整成本门禁、按已声明复用机会的预测、在线认证延迟预算，以及自由表述的动态作用域限制。如果更严格契约降低覆盖，应同时报告收益损失；若独立请求或后台资格协议被采用，raw与策略必须共享同一调度与到达规则，后台工作和最终 drain 也计入完整成本。
